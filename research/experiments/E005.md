# E005 The downstream-matched readout and its first kernel variants
hypotheses: [B1, B3, B4, T6, L1, E1]     parents: [E002]     eval_version: pre-v1     cost: ~2 min cpu per arm
pre-registered: 2026-10-08, BEFORE any local data existed

question: With the age model's own readout (raw z, first 24 dims, intercept, iid prior), how much of the RESOLVABLE
held-out change of dev species is captured, at what attenuation, and does any kernel change the age model could
adopt (split zbar/dz amplitudes, a time basis, a lag) change that?

design: research/exp/fast_arm.py on the desk_tempho_1995 cache (primary: time and space_time groups, 1966-1975
window = 21-30 y past the training edge) and the gp_species_base cache (space group). Arms:
  A0 iso raw r24 (the deployed contract)   A1 iso ema r24   A2 iso raw r64   A3 split raw r24 (ref 1996-2025)
  A4 iso raw r24 + time basis 4            A5 iso raw r24, lag half-life 10
All on the same rows and species (dev half only; sealed species untouched).

predictions (written before data):
- A0 change skill vs no_change on resolvable species: median in [-0.05, +0.10]; attenuation slope median in
  [0.05, 0.4]; level skill vs intercept clearly positive (> 0.2) in every group. I.e. a "modern map": good level,
  little change -- the pattern the user reported as "about no-change on change".
- Most dev species' change is NOT resolvable: n_resolvable / n_species < 0.3 in the time group (E1).
- A3 split: s_w^2/s_b^2 (per-feature amplitudes, medians) > 1, i.e. the data want MORE weight on within-cell
  deviations than the iid prior gives them (B1); change skill up by >= 0.03 over A0 if B1 holds.
- A4 time basis: change skill up materially (>= 0.05) if continental trends dominate dev species' change (C1/B4).
- A2 r64 vs A0 r24: change skill difference < 0.02 unless temporal signal lives in dims 25-64 (B3).
- Interval coverage (90%) in the time group BELOW nominal (< 0.85) if the z.z' kernel is overconfident about the
  past (B2).

decision rule: A3 or A4 gaining >= 0.03 change skill without losing level skill beyond seed noise -> that kernel is
a candidate downstream contract change (escalate after verification); nothing gaining -> the readout is not the
lever, go upstream (E004's DESK readings).
