# E020 How much real ESK content does DESK carry per component -- and is rank 64 worth it?
hypotheses: [R1, B3, T0]     parents: [E004]     eval_version: pre-v1     cost: ~1 min cpu per run
pre-registered: development run first (2026-10-09, base trained + tempho1995 withheld), prompted by the user: the 24-dim
cut was chosen because DESK seemed to carry nothing meaningful beyond it (maybe beyond ~12); 64 is affordable if useful.

design: research/exp/rank_fidelity.py. Held-out cells; per ESK component, the noise-free R2 of DESK's component against
the true component (halves' covariance as the true variance), spatially (modern levels) and temporally (change); the
component's share of true variance; the cumulative variance DESK captures with the first r.

  0.05 -> 0.06 (z_ema similar, slightly higher).

reading (UNVERIFIED): the 24-dim cut IS time-selective -- nearly half of the true place-specific temporal change lives
in components 25-64, against 17% of the spatial structure (temporal change behaves like small spatial differences,
which the leading components do not carry). But DESK cannot use those components: its temporal R2 there is <= 0.07
(<= 0.02 in the backcast), so going to 64 adds +3 points of spatial and +1-4 points of temporal captured variance. The
bottleneck is DESK's temporal fidelity in every band, not the cut; the cut matters only once DESK's temporal fidelity
improves.

predictions for the replications (tempho1985 / tempho1975 withheld): temporal variance share beyond r24 in [0.35, 0.55];
DESK temporal R2 in components 25-64 <= 0.08; captured temporal share gain r24 -> r64 < 0.05.
