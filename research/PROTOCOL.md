# Research loop protocol — why DESK loses temporal signal

Started with `/loop follow research/PROTOCOL.md` (self-paced). Every tick follows this file. If this file,
the generated `STATE.md`, and a compacted conversation disagree, **the files win**.

## Purpose and the two rules that override everything

The age model fits vital rates as Bayesian linear regression on DESK features: H_j = z·β_j, β_j iid across
features (a GP with kernel s_j² z·z'), raw z, first 24 of 64 dims, plus intercepts and a near-zero
continental K trend (`src/model/age_fields.py:176–254`). It must backcast to 1902–1939, where the only data
are non-arrival pseudo-zeros >700 km beyond the native hull. Held-out BBS species' abundance in withheld
decades is the proxy; `research/downstream_contract.md` freezes the contract the loop anchors on.

1. **Understanding before score.** A tick's goal is a sharper question, not a better number. Interventions
   (retraining DESK, rebuilding ESK) run only as tests of a mechanism earlier experiments made specific,
   with the predicted effect written first.
2. **Downstream anchoring.** Every result is read for what it implies about the BLR backcast: level and
   change accuracy in withheld decades (Great Plains zone separately), attenuation slope of predicted on
   true change, interval coverage / implied temporal kernel, responsiveness to absence-only information.

## One tick

0. `rx tick begin`. Exit 3 = STOP (stop the loop: `ScheduleWakeup stop`), exit 4 = another session holds
   LOCK (reschedule 60 min). A reported half-done tick must be finished or rolled back first.
1. If the verdict is **NOOP** (nothing finished, nothing overdue, no `DUE:` in intent.md): `rx tick end`,
   `ScheduleWakeup` at the next ETA (or 60–120 min), and stop. Target ≲3k tokens. Do not read anything else.
2. `rx jobs collect`. Read only the printed summaries. A large output goes to a subagent, never into context.
3. **Verification gate** for anything that would become a finding (below).
4. Update `hypotheses.yaml`: status changes cite registry job ids; never retire a hypothesis on an
   unverified result.
5. **Generate hypotheses.** For each result: what does it rule out; what else would produce it; what would
   separate those; what does it imply for the BLR backcast. Add new entries with `parents`.
6. **Choose** by value of information ÷ cost: prefer the experiment whose possible outcomes would most
   change *which stage we believe loses temporal signal* or *the downstream design*. If no outcome would
   change a belief or an action, do not run it. Keep one GPU job queued whenever a GPU experiment has
   value; CPU analyses run alongside. Every ~5 working ticks: one attempt to falsify the leading hypothesis
   and one open-ended look (maps of change, residual structure, worst species/zone).
7. **Pre-register** (`experiments/EXXX.md`, template below), commit, then enqueue (≤3 new per tick).
   Append to `DIGEST.md`, update `intent.md`, `rx tick end`, commit, push the branch (at most hourly),
   `ScheduleWakeup` (next ETA if <30 min away, else 60–120 min). Before an expected idle stretch
   (usage-window end, overnight) front-load the GPU queue.

## Pre-registration template (`experiments/EXXX.md`)

    # EXXX <title>
    hypotheses: [R1, T0]     parents: [E00Y]     eval_version: v1     cost: ~N min cpu|gpu
    question: one sentence
    design: data slice, rows/species, arms (with blinded codes), metric(s), seeds/splits
    predictions: under each rival hypothesis, the expected sign/size of each metric
    decision rule: which outcome moves which hypothesis where, and what runs next in each case
    ---- (appended after the run) ----
    results (registry jobs ...), verification a/b/c/d, interpretation, surprises, spawned hypotheses

## Verification gate — a FINDING needs all four

- (a) the analysis code recovers a planted answer under the real sampling design;
- (b) the headline is re-derived by a second, independent, short code path;
- (c) it survives a second seed, split, or species half;
- (d) a skeptic subagent, given only the record and the code, names the cheapest artifact explanation and
  its test — run that test if cheap.

Arm labels in summaries stay blinded until the interpretation is written. Unverified results may steer
exploration but may not retire a hypothesis, trigger training, or appear in DIGEST as conclusions.

## Guards

- **Sealed species.** A random half of out-of-community species is sealed (Phase 1.6). Only
  `research/adopt.py` reads them, each read is logged; reading them otherwise is a protocol breach.
- **Evaluation freeze.** After `eval-v1`, the evaluation modules (`validate_gp_species.py`,
  `gp_kernels.py`, `gp_species_analysis.py`, `validation_core.py`, `validate_bbs_routes.py`,
  `research/exp/fast_arm.py`, `research/exp/atlas.py`) change only through a version bump: bump
  `EVAL_VERSION`, mark older results `stale` in the registry, rerun the anchor experiments, and escalate if
  an anchor disagrees.
- **Seeds.** ≥3 seeds for any training-level claim; seed variance measured on the temporal metric itself
  (the 6.6% floor is a spatial metric's).
- **Budget.** Respect `budget.json`; when a cap is hit, escalate rather than continue.

## Cost ladder (try the cheaper rung first)

0 cached arrays (s) → 1 closed-form surrogates (min; e.g. ridge covariates→ESK with separate between/within
weights, `scripts/diagnostics/component_predictability.py`) → 2 probes/fine-tunes of existing checkpoints:
25 desk_hp + 3 tempho runs (≤1 h) → 3 short-schedule DESK, only after `rot_ratio` trajectories show
temporal structure is not learned late → 4 full DESK (≥3 seeds) → 5 human-gated age-model MAP with two
feature maps. A surrogate earns trust only by picking the same winner as the full runs on existing pairs
whose gap exceeds seed noise; negative fine-tune results are weak evidence.

## Escalate (PushNotification + DIGEST entry, then pause) when

a verified result implies changing production configs, the downstream model, or acquiring covariates; a
verified result contradicts an earlier project result; an anchor rerun after an eval bump disagrees; disk
or GPU trouble; a budget cap is hit; or nothing open has positive value. Digest to the user every ~2 days
of looping. Never submit TACC jobs, never delete data, never touch `main`.
